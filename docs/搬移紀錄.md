# 自 Systemautofill v1.00 搬移紀錄

## 基準

在 v1.00 原專案執行完整測試（不連真實瀏覽器）：256 通過、0 失敗。其餘錯誤來自需要真實 Chrome 的 `test_browser.py`，以及缺少圖形函式庫的 3 個 Qt 介面測試，皆與核心邏輯無關。

## 已搬入 `bridgefill/core/`

26 個模組，內容未改寫，只調整以下兩處：

| 模組 | 調整 |
|---|---|
| `deru.py`（新） | 自 v1.00 `navigation.py` 抽出 `deru_records`、`deru_status`。原檔匯入 Playwright，抽出後 `reporting.py` 改由此匯入 |
| `local_files.py` | 專案根目錄改為往上兩層（`parents[2]`），因模組移到 `core/` 子目錄 |

模組清單：alignment、binding、case_identity、comparison、conditions、config、data、deru、document_scan、document_style、documents、header_document、id_document、inspection、local_files、locations、naming、policy、progress、rating_review、reconcile、remarks、reporting、scanned_document、sections、view_helpers。

## 已搬入的測試

23 個測試檔，匯入路徑由 `bridgefill.X` 改為 `bridgefill.core.X`。

| 結果 | 數量 | 說明 |
|---|---|---|
| 通過 | 159 | |
| 略過 | 37 | 經由舊 Flet 介面（`ui_helpers.ui()`）驗證流程的測試；`tests/ui_helpers.py` 改為呼叫時自動略過 |

同一批測試檔在 v1.00 原專案為 191 通過，差額即為上述介面測試。

## 尚未搬入（第 2～6 步重寫）

| v1.00 模組 | 原因 |
|---|---|
| `app.py`、`qt_app.py`、`qt_widgets.py`、`inspection_ui.py`、`inspection_editor.py` | 舊介面（Flet 與 PySide6 並存），改用新版型重寫 |
| `browser.py`、`navigation.py`、`control.py`、`chrome.py`、`temporary.py`、`controller.py` | 以 Playwright＋外部 Chrome（CDP）為前提，改為內嵌 QtWebEngine 重寫 |
| `bootstrap.py`、`portable_check.py`、`import_memory.py`、`cache_cleanup.py`、`vault.py`、`diagnostics.py`、`document_repair.py` | 安裝、可攜版與維運工具，待新架構穩定後視需要搬入 |

`test_browser.py` 的 108 個測試記錄了 v1.00 的防錯行為（送出只送一次、回讀核對、中斷續填不重送、ID 變動即停止等），重寫填寫流程時要逐條對照，確保新版保有相同保護。

- `core/inspection.py` 的 `read_header`、`write_header` 直接操作網頁（`scope.locator`、`page.expect_navigation`），屬於網站操作，應移到 `site/`。目前以參數傳入頁面物件，不匯入瀏覽器模組，所以暫時留在 core。
