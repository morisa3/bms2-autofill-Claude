# 唯讀掃描測試（第 3 步）

在內嵌網站中開啟一期檢測，程式自動讀取每一列構件的缺失清單與欄位，並核對「詳細資料(n)」的筆數。

**全程只讀取，不送出、不修改網站資料。** 程式只會開啟唯讀清單內的網址（列表、編輯頁讀取、基本資料），含刪除、更新、新增的網址一律拒絕；每讀一頁暫停 0.5 秒，避免對網站造成負擔。

## 執行方式

1. 下載最新的分支 ZIP（和登入測試相同），解壓縮到**同一個資料夾**，沿用 `browser-profile` 就不用重新登入。
2. 雙擊 **`掃描測試.bat`**。

## 測試步驟

| 步驟 | 動作 | 預期結果 |
|---|---|---|
| 1 | 按上方「定期檢測查詢」，輸入橋名查詢，在結果列表按該期的「修改」，開到**缺失主頁面** | 頁面正常顯示（網站最上層選單也可以點一下展開） |
| 2 | 按「只核對筆數（較快）」 | 右側表格列出每一列構件；讀到筆數與網站筆數一致的顯示 ✔，不一致的列標紅 |
| 3 | 按「掃描目前檢測」 | 同上，另外讀取每筆缺失的第二級欄位（工法、數量、單位、單價、備註） |
| 4 | 按「掃描基本資料」 | 下方紀錄列出淨寬、橋下淨高、跨距分配孔數、橋孔資料表孔數、各孔主梁根數 |
| 5 | 在**本期**主頁面按「掃描前期」 | 程式從歷史定期檢測紀錄找出前一期，以「檢視」頁讀取；紀錄列出前期日期與檢測人員，維修狀態欄顯示已維修／部分未維修／未維修 |

建議先用缺失較少的橋（例如神木橋）試，再試龍門大橋。龍門大橋約 120 列，步驟 3 預計 5～10 分鐘；中途可按「停止」。

## 測完請回傳

1. 按「開啟結果資料夾」，把 `temp/scan` 裡的 `*.json` 傳給我（內含掃描到的缺失資料，請確認可以提供）。
2. 告訴我：
   - 各步驟花了多久？
   - 右側有沒有標紅的列？紅色列的「核對」欄寫什麼？
   - 有沒有跳出錯誤訊息，或卡住不動？

## 網站提示視窗

- 畫面上的網站頁面：提示視窗照常跳出，由你自己判斷。
- 掃描用的背景頁面：提示視窗不能停下來等人按，否則掃描會卡住。提示訊息會記在紀錄裡並自動關閉；**確認類視窗（例如「確定刪除？」）一律取消**。

## 本期與前期的讀取方式

| | 第二級讀取 | 原因 |
|---|---|---|
| 本期（「掃描目前檢測」） | 編輯頁（只讀欄位值，不送出） | 要核對建議維修工法 ID，並收集各構件的劣化類型選項 |
| 前期（「掃描前期」） | 檢視頁（純顯示） | 前期只需要內容；檢視頁沒有 ID，以網址上的 der_id 對應第一級的 ID |
