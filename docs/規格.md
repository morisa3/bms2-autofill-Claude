# 新版規格（討論確認紀錄）

本文件記錄與使用者討論後確認的決策，作為新版開發依據。尚未確認的項目列於最後「待確認」。

## 1. 技術方向

| 項目 | 決定 |
|---|---|
| 語言 | Python |
| 介面 | PySide6（不用 Flet：網站內嵌、大量表格、意見文字編輯都需要 Qt） |
| 瀏覽器 | 以 QtWebEngine 內嵌 bms2 網站；需先實測登入（見第 6 節），不通過則保留外部 Chrome |
| 改版方式 | 方案 ③：新專案，從 Systemautofill v1.00 搬入純邏輯模組及其測試；介面、瀏覽器、流程重寫。舊版 v1.00 照常使用至新版功能跟上 |
| 資料來源 | 以線上唯讀掃描為主（基本資料、前期、本期）；Word 只當備援 |
| 資料鎖定 | 本期一律以網站劣化 ID 鎖定，不依 Word 或網頁順序 |

## 2. 操作版型

採 **A 當外框，右側面板切換 B／C**：

- **A 外框**：左側內嵌網站（前期／本期可分頁或並排，前期可隱藏），右側助手面板。螢幕寬度小於 1600px 時網頁區改為分頁、不並排。
- **B 逐筆審查**：一次一筆，只列異常與需確認項目。
- **C 總表**：一列一組配對（構件、位置、前期備註、本期備註、判定、信心），雙擊展開為 B 的編輯卡；也用於核對下包資料。
- 流程收成三步：**掃描 → 審查 → 填寫**。

## 3. 網站結構（依使用者提供的 XPath 與網頁原始檔）

- 缺失主頁面各構件表以 table id 定位（`approach_bank`、`abutment`… 見 `bridgefill/core/config.py` 的 `COMPONENTS`）。
- **不得寫死欄位或列號**：有無「狀態」欄會讓欄位整欄右移；應讀表頭文字找「詳細資料」「DERU」「維修狀態」欄，再逐列讀取。
- XPath 文件更正：
  - 引道路堤（有狀態欄）橋尾 DERU 應為 `//*[@id="approach_bank"]/tbody/tr[3]/td[6]`（原文件誤植為 tr[2]）。
  - 鋼纜錨碇裝置（橋塔端）`tr[21]` 只是範例橋梁中唯一有缺失的那列（TA20-L），不是固定位置。
- 鋼纜（吊索）與鋼纜保護套管共用 `stay_cable`，以區段標題 span 區分。
- 箱涵構件（鹿-13 確認）：端牆 `headwall`、中隔板 `midwall`、頂板 `top_slab`、底板 `bottom_slab`，各有專屬的劣化類型選單（見 Excel 箱涵工作表）。
- DERU 顯示：
  - `_ 0 _ _`：E＝0（無法檢測），D 留空，無劣化 ID。
  - D＝1：良好，無劣化 ID。
  - 完整數值（例 `3 1 3 3`）：有缺失，需讀第一級頁面。
- 維修狀態欄有三種值：**已維修**、**部分未維修**、**未維修**。
- 「詳細資料(n)」的 n 為第一級頁面的筆數。D＝1／E＝0 的列固定顯示 (1)，那 1 筆是照片紀錄，不是缺失。
- 編號保留左右側（如 `TA01-L`），位置正規化不得刪除 `-L`／`-R`。
- 主梁編號格式為 `S1G1`（第 1 孔第 1 根），備註中的 `1G1` 即 `S1G1`。
- 網址與識別（由網頁檔確認）：
  - 缺失主頁面每列的「詳細資料」連結帶 `component_form`、`component_id`、`inspect_id`、`inventory_id`，構件以 component_id 識別。
  - 缺失主頁面的 DERU 是彙總值；多筆時各筆 DERU 要看第一級頁面。
  - 第一級每筆有 D／E／R／U、劣化類型、建議維修工法 ID（網站唯一 ID）、`der_id`，已維修者另有「已維修」連結。
  - 第二級表單隱藏欄位 `id` 即建議維修工法 ID；劣化類型下拉選項依構件不同。
  - 橋護欄表格有「橋護欄高度」欄，可直接用於護欄高度規則。
  - 基本資料 `/basic/inventory/edit/{inventory_id}/`；構件／擴建 `/basic/extended/list/inventory_id,{id}/`；各構件 `/basic/member/list/extended_id,{ext}/`；橋孔與主梁以網站列表函式 `xajax_set_action_ajax('…/list/…')` 載入。
  - 歷史定期檢測紀錄 `/inspect/inspect/result/inventory_id,{id}/from,inventory/`：依日期由新到舊，每列有檢測系統 ID（inspect_id）、日期、檢測人員；「修改」連結 `/inspect/inspect/der_content/inspect_id,X/…` 即缺失主頁面。前期＝日期早於本期的最新一筆。
  - 網站的第一級、第二級是彈出視窗（easy.js 以 iframe 載入連結網址）。程式不操作畫面上的彈出視窗（v1.00 操作時常遇到無法關閉、主頁面來回捲動），改以背景頁面**直接開啟同一網址**讀取，等同另開視窗；2026-11-14 實測可正確讀取。
  - 實際網頁的連結寫法：缺失主頁面為 `/bms3/inspect/…`；第一級、第二級、歷史紀錄頁為 `inspect/…`（沒有斜線），以頁面的 `<base href="https://bms2.iot.gov.tw/bms3/">` 為基準。另存網頁時 Chrome 會轉成完整網址，所以網頁檔看不出差異。解析時一律依 `<base>` 補成完整網址。
  - 網頁內容一律以 toHtml 取回；在使用者的 Windows 電腦上，腳本回傳值會變成空字串，不能用來傳資料。
  - 「返回列表」按鈕為 `xajax_redirect_last('result')`，由伺服器記錄上一個列表，網址不固定；歷史紀錄改以 inventory_id 組網址。
  - 跨距分配可能帶單位（例：`1@35M`），也可能有資料錯誤（例：產業一號橋 `2040M+…` 疑似漏了加號）；與總橋孔數、橋孔資料表孔數不一致時提示，以橋孔資料表為準。
  - 第二級「檢視」頁 `/inspect/damage/view_damage/der_id,X/…`：純顯示，沒有表單與建議維修工法 ID。前期以檢視頁讀取，本期以編輯頁讀取（不送出）。
- 基本資料：`#width_min`、`#width_max`、`#distribution`（例 `25+1@42.5+2@40+4@40+4@40+30` 表示 S1～S13 跨距，`n@L` 為 n 孔各長 L）。

## 4. 掃描與核對

- 前期：唯讀掃描，不需保存 ID，必須讀取維修狀態。
- 本期：掃描並保存每筆劣化 ID。
- 筆數核對（每一列）：
  - 網站 n ＝ 讀到筆數 → 正常
  - 讀到少於 n → 提示漏讀，重掃該列
  - 讀到重複 ID → 提示重複
  - D＝1／E＝0 的列：n＝1 視為正常，不算缺失
- 漏填檢查（核對下包資料）：

| 階段 | 欄位 | 程式行為 |
|---|---|---|
| 現場必填 | 劣化類型、DERU | 網站本身強制，不另外檢查 |
| 辦公室補齊 | 損壞位置、維修工法、數量、單位、單價、備註（含完整尺寸） | 任一空白或備註尺寸不完整即列為漏填 |
| 不檢查 | 劣化範圍（長、寬、高）、損壞原因 | 忽略（尺寸統一寫在備註） |

## 5. 配對

- 只在「同構件＋同位置列」內找候選，全域一對一配對。
- 判定分類：沿用、範圍加大、單位數量變更、新增、已維修（前期已維修、本期無）、**疑似漏建**（前期未維修或部分未維修、本期無）。
- 現場可能只填劣化類型與 DERU：
  - 同一列只有一筆同類型前期 → 直接鎖定，帶入前期工法、數量、單位、單價、備註。
  - 同一列有多筆同類型前期 → 列為需確認；掃描時先標出這些列，提醒現場在備註寫可區分的短詞（如 `A2-L`）。
- DERU 只作輔助線索，不單獨決定配對。
- 2.1（劣化類型判斷不同但同一筆）需「劣化類型等價表」，由使用者提供。
- 備註自動產生：

| 單位 | 備註尺寸 |
|---|---|
| m | `(m)*1` |
| m（裂縫） | `(mm*m)*1`；寬度大於 10mm 轉為 `(cm*m)*1` |
| m² | `(m*m)*1`，後方的 m 為長度 |
| m³ | `(m*m*m)*1` |

- 引道路堤缺尺寸時以「最小淨寬 × 5m」補，例：淨寬 8m → `A1 AC剝離。(8m*5m)`。

### 配對引擎（`bridgefill/core/matching.py`，第 4 步）

- 列對列：前期與本期以網站構件識別（component_form＋component_id）直接對上。2026-11-14 產業一號橋實測：前後期 60 列構件 ID 完全一致。
- 列內計分（滿分約 103）：樣態相似度 ×50、劣化類型相同 +15（由「其他損傷」等改為具體類型 +10）、位置相同 +20／寫法不同 +10／不同 −15、單位相同 +10（前期為「式」+5）、數量相同 +5、D 相同 +3；樣態相似度低於 0.5 扣 10。互斥樣態（木本／草本、齒型／角鋼、鋼管／鋼筋、AC／混凝土、瀝青／混凝土）一律不配對。
- 一對一組合取總分最高；45 分以上才配對，75 分以上且沒有相近競爭者為「高」信心，其餘「需確認」。
- 位置正規化：損壞位置欄位若混入樣態文字只取開頭英數代碼；`S1G1` 與 `1G1` 視為相同。
- 同義詞（暫寫在程式，之後由 Excel「樣態同義詞」提供）：滲水＝漏水、未設置護欄＝缺口、雜物堆積＝積土等；滲水白華不分字序與連接詞（白華且滲水、滲水及白華）。
- 沒配上的本期與前期若位置相同，互相註明「可能對應」，供人工判斷（需求 2.1）。
- 同一列只剩一筆前期、一筆本期，位置與單位相同時，判為同一筆並標「需確認」（使用者確認 4G1-20R 銹蝕蜂窩＝混凝土剝落鋼筋外露）。
- 本期備註位置與所在構件不符時（例：S3 那列寫成 S4）加註「本期備註位置 S4 與所在構件 S3 不符」並標「需確認」。主梁編號 4G1 視為 S4。
- 疑似漏建可能是自然消失（例：河道掛淤被河水沖走），程式無法判斷，維持需確認；第 5 步介面提供「已消失」選項。
- 產業一號橋（2026-11-15 使用者逐筆核對）：程式判為「高」的 46 筆全部正確；3 筆需確認與使用者判斷一致。核對檔存為私人測試資料，作為回歸測試。
- 準確率（`tools/evaluate_matching.py`，以使用者確認過的配對為答案）：竹子坑橋 53 筆、木馬寮橋 43 筆全部正確。原比對檔有 2 筆答案經使用者 2026-11-15 更正（P2 雜物堆積為沿用；P1-正 混凝土蜂窩對應前期 P1正 混凝土蜂窩），更正記錄在評估程式的 CORRECTIONS。

## 7. 檢測員意見

### U 值與建議文字

| U | 建議 |
|---|---|
| 2 | 持續追蹤，或三年內派工修復（判斷見下） |
| 3 | 一年內派工修復 |
| 4 | 需緊急處置 |

U＝2 的判斷標準是「是否影響橋梁安全或行車安全」：

1. **橋面上的缺失**：影響行車安全 → 三年內派工修復。
2. **下部結構**：先看是否為主構件，再看劣化面積。
   - **劣化面積大＝E≧3**（劣化範圍 30% 以上，手冊表 4.1）→ 三年內派工修復。
   - 面積小（E≦2）→ 持續追蹤，**主構件 E＝2 也是持續追蹤**。單位為「處」一般即為小面積。
   - 混凝土剝落、沖蝕、小破裂的維修優先級低於混凝土剝落鋼筋外露；小面積且 U＝2 時，常不寫入意見。
3. 系統會追蹤 U 值突然下降的構件；與前期相符的劣化，一般不調整 U 值。新版配對成功時預設沿用前期 U，本期 U 低於前期要提示。
4. 位置寫「-All」時 E 一般為 4；不是 4 時提示。

構件分類依《橋梁檢測手冊》第四章（上部結構、下部結構、橋面系統及附屬設施、河道及相關設施），見 Excel「構件分類」工作表。手冊明訂主梁為主構件、橫隔梁為次要構件，其餘為草稿待確認。

### DERU 評等（手冊表 4.1）

| | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 程度 D | 無此項目 | 良好 | 尚可 | 差 | 嚴重損壞 |
| 範圍 E | 無法檢測 | 10%以下 | 10%～30% | 30%～60% | 60%以上 |
| 重要性 R | 無法判定 | 微 | 小 | 中 | 大 |
| 急迫性 U | 無法判定 | 例行維護 | 3年內維護或持續追蹤 | 1年內維護 | 緊急處置 |

E＝0 為無法直接目視評等（如地面下之橋台基礎、橋墩基礎）。

### 由竹子坑橋（程式原稿 vs 最終版）歸納的修正規則

1. 選項要先選定：`建議採【加高／重作】` → 生成前讓使用者選。
2. 基礎裸露要加深度判斷：自動計算裸露深度占基礎深度的比例（1/5、1/3）；基礎深度與治理計畫等本橋特有文字從**前期意見沿用**。
3. 位置只寫到主構件：去掉細部位置（`A1-下游` → `A1`），主梁、橫隔梁編號換成跨號（`1G1-0,13,26` → `S1`）。
4. 構件名稱用實際名稱：斜線構件取實際那一個（`翼牆／擋土牆` → `擋土牆`）；樣態已含名稱就不重複；`其他`、`整體-` 刪除。
5. 相同樣態、相同建議的條目合併（`S1~S3主梁、橋面板混凝土剝落鋼筋外露`）。
6. 不重要的樣態不寫入意見（例：伸縮縫漏水、基礎混凝土剝落、蜂窩、AC 剝離），以 Excel「意見範本」工作表的排除清單管理。
7. 第 1 條已敘明基礎裸露時，刪除後面重複的「橋墩基礎裸露」條目（龍門大橋第 16 條同理）。

### 淨高

- 格式：單跨 `H=[]m`；多跨 `P1=[]m,P2=[]m,...`。
- 本期有新值則保留；沒有則沿用前期意見中的值。
- 意見要針對哪些構件，生成前先勾選。

## 8. 尺寸合理性檢查（以橋梁基本資料推估構件面積）

備註尺寸與橋梁基本資料對不起來時提示，並以下列經驗數據提供參考值；不自動改寫，由檢測員確認。

| 資料 | 來源 |
|---|---|
| 各孔跨距 | 基本資料 `#distribution`，或橋孔資料表「跨距(M)」欄 |
| 全寬 | 橋孔資料表「全寬(M)」欄（全寬＝淨寬＋兩側護欄寬） |
| 淨寬 | 基本資料 `#width_min`、`#width_max`（用於路面） |
| 最低橋下淨高 | 基本資料 `#height_below` |
| 各墩淨高 | 前期檢測員意見中的 `H=`、`P1=…` |
| 主梁根數 | 橋孔資料表每列第 1 欄的「主梁(n)」按鈕（`td[1]/a[2]`）→ 主梁明細頁 `table#main` 的資料列數（例：S1G1、S1G2、S1G3 為 3 根）。按鈕上的 n 不是根數，不可直接使用 |

| 構件 | 推估方式 |
|---|---|
| 引道路堤 | 最小淨寬 × 5m |
| 橋面板（整孔） | 跨距 × 全寬 |
| 橋面板（分格） | 兩側懸臂版各 0.7～1.3m；梁與梁之間 ＝（全寬 − 兩側懸臂 − 主梁根數 × 梁寬）÷（主梁根數 − 1） |
| 主梁 | 梁寬 0.4～0.7m，配合全寬修正 |
| 墩柱與帽梁 | 面積上限 ＝ 全寬 × 淨高 × 0.7～0.8（高估版本，常為 T 字型墩柱） |

用途：
- 劣化尺寸超過構件推估面積 → 提示尺寸可能有誤。
- 劣化面積 ÷ 構件推估面積 → 對照 E 值範圍（表 4.1），差距過大時提示。

範例（龍門大橋 S1）：跨距 25m、全寬 9.1m、淨寬 8m。橋面板整孔約 227.5m²。假設主梁 3 根、梁寬 0.55m、懸臂 1.0m，梁間橋面板每格寬約（9.1 − 2.0 − 1.65）÷ 2 ≈ 2.73m。（龍門大橋實際主梁根數尚未取得；目前的主梁明細頁網頁檔為神木橋 S1，共 3 根 S1G1～S1G3）
